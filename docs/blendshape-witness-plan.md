# Blendshape closure witness: do mesh points the aperture ignores carry closure the eyelid rim does not? — written before any blendshape trace is read

Written 13 September 2026, and committed **before any blendshape trace is read**, in the predict-then-verify discipline — the same discipline as `docs/iris-occlusion.txt`, `docs/pupil-light-plan.md`, `docs/drozy-analysis-plan.md`, `docs/uta-rldd-plan.md`, and `docs/alertness-score-plan.md`. It is roadmap row 12.3, and it runs on the Eyeblink8 regression harness before any sibling corpus is opened. The commit that adds this file contains **no result**. The result arrives in a later commit — a `CONFIRMED`/`null`/etc. verdict with its numbers in `docs/blendshape-witness-result.txt` — and can be checked against what is written here. The plan is not edited after the data is read.

## The question

Over the ~49-miss shallow-aperture ceiling the awake-corpus autopsy left standing (`docs/miss-character.txt`, `docs/iris-occlusion.txt`), does the vendored MediaPipe blendshape head — a landmark-fed network over 146 mesh points — register eye closure on the very frames a human marked fully shut but the geometric aperture did not, i.e. does a learned nonlinear read of the mesh recover closure that the fixed 12-point eyelid-rim ratio discards?

## Why this experiment, and why it is the honest test

The 49-miss ceiling has already survived two knives. Moving the personal blink line cannot reach it (the aperture never dipped decisively on these frames), and a second landmark-derived closure signal did not fall on it either: the iris-occlusion witness recovered **0 of 49** (in-span iris median 0.846 against a 0.877 open baseline, a +0.024 non-drop, 0 of 49 with any in-span frame below its 0.70 collapse bar; `docs/iris-occlusion.txt` lines 103-119). The blendshape head is the only vendored instrument left that could see past that ceiling, and this experiment is the fair test of it.

**The honest prior is skeptical, and it rests on a provable containment, not a mood.** The blendshape network is confirmed **landmark-fed, not an appearance head** (Google's "Mediapipe Blendshape V2" model card: "predict 52 facial blendshapes FROM FACIAL LANDMARKS"; the C++ `face_blendshapes_graph` takes only a `LANDMARKS` stream and `IMAGE_SIZE`, never a pixel tensor; roadmap 12.3 states the same). It sees only the geometry FaceMesh already extracted — the 2D X,Y of 146 mesh points — and it consumes a **strict superset of the very landmarks the aperture uses**: the 12 EAR points (`src/core/constants.ts`: 33,133,160,144,158,153 and 263,362,387,373,385,380) and indeed all 32 eyelid-rim points are members of the network's 146-point input subset, and neither instrument gets a depth channel. So on a miss caused by FaceMesh itself failing to move the lids into the mesh, **the closure is not in the input to either instrument**, and enabling the head changes the readout but not the input. That is why the a-priori expectation on this shallow set is correlated failure — the null — and why a low recovery count here is a strong, mechanistically-explained ceiling result rather than an artefact.

**The honest counterweight, committed alongside, is the reason the experiment is worth running at all.** The rim ratio is bounded by a hand-chosen formula over 6 points per eye; the network is bounded only by what the whole 146-point mesh encodes, and the gap between those two bounds is real. The network can weight the periocular points the EAR throws away (the other 10 points of each lid ring, the brow rim, the cheek), it is trained end-to-end on the blink manifold rather than being a geometric identity, and it was trained with noise augmentation on its input landmarks — exactly the jitter that most corrupts a bare 6-point ratio. So on a miss where the closure _is_ present in the wider point cloud and the rim ratio merely discards it (formula-limited, not mesh-limited), a learned read is the one vendored route with a genuine chance to recover it. Both outcomes are pre-registered as results, and a null is published exactly as readily as a positive one would have been.

## What the neutrality control must establish first

Enabling the blendshape output is a pure additional _output_ branch of the fixed MediaPipe graph: the face-blendshapes subgraph is downstream of and fed by the landmark subgraph, consumes the already-computed landmarks, and never writes them; and nothing in the aperture/blink chain reads `result.faceBlendshapes` (grep finds no consumer in `src/`). Turning `outputFaceBlendshapes` on therefore must not perturb `result.faceLandmarks[0]` or `result.facialTransformationMatrixes[0]`, so no landmark-based measurement can move. Prediction 1 below commits this as a falsifiable claim, because it is the control that _licenses_ attributing any recovered miss to the blendshape signal rather than to the landmark numbers shifting when the flag flipped. Predictions 4-10 are void unless Prediction 1 holds.

## The extraction contract and the pre-committed threshold, fixed in advance

**The flag.** The only change from the committed anchor is `outputFaceBlendshapes` false -> true (`src/io/landmarker.ts`, both delegate arms; `MODEL_CARD.md` line 336 flips with it). Everything else is held at the anchor: same model file (`face_landmarker.task`, sha256 `64184e22...`), same `@mediapipe/tasks-vision` 1.0.1 as the lockfile pins, same WebKit and Playwright revisions, same stepped `measurement_mode` with `inexact_landings = 0` on all 8 clips, same corpus, same delegate outcome. The witness table is computed by a new committed tool, `analysis/tools/blendshape_witness.py` (sibling of `analysis/tools/iris_positive_control.py`), joining the flag-on per-frame `eyeBlink` trace to `docs/evidence/2026-09-02-awake-autopsy/eyeblink8_miss_autopsy.csv` by `(clip, blink_id)`.

**The threshold T, committed here before any trace is read: T = 0.50** on the model's [0,1] activation-coefficient scale. The model card pins these 52 outputs as blendshape _activation coefficients_ (0 = lid neutral/open, 1 = lid fully lowered/closed), not probabilities, and roadmap 12.2 pins that [0,1] contract. 0.50 is the exact midpoint — the symmetric boundary between "closer to open" and "closer to closed," carrying no data-tuned bias toward confirm or refute. Choosing the lenient midpoint rather than a strict 0.8-0.9 is deliberate for a null-prior test: it hands the witness every benefit of the doubt, so a low recovery count under T = 0.50 is a strong result rather than an artefact of a harsh cut. T is committed in this plan so it cannot be moved to manufacture a count; its calibration is not assumed but **tested** by the caught-blink positive control (Prediction 2), and if that control fails, T is re-derived under its own separate pre-registration before any recovery number is scored. A sensitivity sweep at T in {0.30, 0.50, 0.70} is computed and all three fire-counts reported; the decision rule reads T = 0.50 only.

**The per-frame witness coefficient: `eyeBlinkMax(f) = max(eyeBlinkLeft(f), eyeBlinkRight(f))`** (indices 9, 10). Blinks are bilateral; taking the more-closed eye (not the mean, not both) is the maximally-generous reading and cannot be defeated by a one-eyed landmark wobble — the generous rule that makes a low count the strong null. Per-eye peaks and the peak-of-mean are stored so a mean- or min-rule rescore is auditable, and the verdict is reported at the min-rule and max-rule and at T in {0.40, 0.60} as a ride-along robustness band; the committed verdict is `eyeBlinkMax` at T = 0.50.

**"Witness FIRES on miss m"** := `peakBlink_span(m) >= T`, where `peakBlink_span(m)` is the max of `eyeBlinkMax` over every measured frame in the miss's `[startFrame, endFrame]` span. Max over both eyes and the whole span is the generous primary.

**"Witness RECOVERS miss m"** := miss m has a fully-closed frame AND `peakBlink_closed(m) >= T`, where `peakBlink_closed(m)` is the max of `eyeBlinkMax` over the human-marked fully-closed frames. Recovery — not mere firing — is the scored quantity, because a fire on a non-closed frame is not evidence the witness saw the closure the aperture missed.

**The usable-data gate, fixed here before the data.** The witness is scored only where the neutrality control holds byte-for-byte (Prediction 1); any miss whose row is not byte-identical with the flag on is disqualified from scoring. For the `no_trusted_face` group, whose aperture is null on every span frame (`measured_frames = 0`), the re-run must record `result.faceBlendshapes[0]` **directly from the MediaPipe result on those frames, independent of the app's pose/trust gate** (`main.ts:3836`); without that direct recording the group cannot fire and Prediction 10 is untestable, so this recording is pinned now.

## The prediction (numbered, each falsifiable)

The no-signal reference throughout is the shared-input bottleneck: **~0 recoveries beyond what the aperture already sees**, corroborated by the iris witness's 0 of 49. The full-headroom alternative is a subtype's full size (an appearance-grade head that truly saw these closures would fire on nearly all of them, with `peakBlink_closed` near 1.0). Each prediction states the expected (skeptic) outcome, the number that would confirm the null, and the number that would refute it.

**Prediction 1 — NEUTRALITY (the licensing control, committed before the corpus run).** Take the committed anchor and change only `outputFaceBlendshapes` from false to true; hold everything else fixed as above; re-run the Eyeblink8 regression harness (`docs/regression-run-procedure.txt`) and regenerate the miss table. Claim: the produced `eyeblink8_misses.csv` is **byte-identical** to `docs/evidence/2026-08-21-rearm/eyeblink8_misses.csv` — the same 67 rows, in the same corpus-walk order, with identical `clip`/`blink_id`/`startFrame`/`endFrame`/`frameLength`/`fullyClosedFrames` digits and identical CRLF framing. In the stronger equivalent form the harness checks where traces exist: for every clip the per-frame `apertureMm` series, and therefore the per-frame blink log, is identical between the flag-off and flag-on runs. **Confirm:** byte-identical. **Refute:** any row appearing, disappearing, being replaced, or reordering, or any clip's per-frame aperture series differing. A refutation cannot mean the blendshapes "improved" the landmark measurement — there is no path by which the output branch writes landmarks — so it points at exactly one of a graph-construction side effect that perturbs the landmark numerics, a confounded A/B (a delegate/browser/model slip), or run-to-run nondeterminism; each is a defect in the experiment that makes the headline comparison uninterpretable until it is removed, not a discovery about eyelids. Predictions 4-10 are void if this fails.

**Prediction 2 — POSITIVE CONTROL, caught-blink dynamic range and T calibration (does it fire on anything?).** On the fixed set of **all detector-hit blinks of the awake-corpus run that contain at least one human-marked fully-closed frame** (the correctly-paired complement of the 67 misses; the awake corpus annotates 341 caught + 67 missed = 408 blinks; no sub-selection is permitted, so the denominator is fixed by this rule, not chosen after the traces), `peakBlink_closed >= 0.50` on **>= 90%**. **Confirm (control passes, T sane):** >= 90% fire. **Refute / VOID:** < 90% fire — T = 0.50 is miscalibrated for this model at these optics, or `eyeBlink` does not track closure here; T is re-derived from the caught-blink distribution under its own pre-registration and the run repeated, and no miss-recovery number is scored until this passes. Grounds: "does it fire on the misses" is meaningless unless it fires on closures it plainly should; this is the control the iris result flagged as its honest next check, run up front.

**Prediction 3 — POSITIVE CONTROL, deep closures the mesh plainly resolved.** These are deep closures the geometry unambiguously showed, so a stateless closure witness must register them. (a) On the **5 `armed_then_dropped` misses** (min_ratio 0.26 to 0.45, deep closures the state machine dropped), the witness fires on **>= 4 of 5**. (b) On the **9 long crossed_line misses** (deep, fully_closed_frames 13 to 24), the witness fires on **>= 8 of 9**. The bar is split so one soft category cannot sink the whole run, and the `armed_then_dropped` group carries the disclosed b30 caveat. **Confirm:** (a) >= 4 of 5 AND (b) >= 8 of 9. **Refute / renders the run INCONCLUSIVE:** (a) <= 3 of 5, or (b) <= 7 of 9 — a witness that misses closures the landmarks plainly resolved cannot license any statement about the shallow set. Reference: a working coefficient reads ~1.0 on any resolved closure; near-100% expected.

**Prediction 4 — HEADLINE RECOVERY over the 30 closed-frame shallow misses (the scored question).** The witness recovers **FEW: recovered30 <= 7 of 30** (< ~25%). **Confirm the null (ceiling):** recovered30 <= 7. **Partial (the per-miss table is the result):** recovered30 in [8, 14]. **Refute the null (substantial headroom):** recovered30 >= 15 — at 15 the network reports the majority of these human-marked closures as majority-activated, which is exactly the point at which the median `peakBlink_closed` crosses 0.50, so the boundary is principled rather than arbitrary. These three regions are disjoint and committed now, so no analyst can pick the branch after seeing the count. Reference values: pure bottleneck ~0 (the iris gave exactly 0/49); a head that truly saw these closures >= 23 of 30 (>= 75%), `peakBlink_closed` near 1.0. Grounds: `eyeBlink` reads a strict subset of the same 146 points with no pixel channel, so on frames FaceMesh never moved the lids the coefficient has nothing to read. Honest counterweight: the network is a learned nonlinear read of all 146 points, noise-augmented, so it may recover several the 12-point ratio discards — which is why the confirm bar is the permissive 7, not 1.

**Prediction 5 — FIRES ANYWHERE over the full 49 shallow misses (the loose cross-check).** `peakBlink_span >= 0.50` on **fewer than 12 of the 49** (the bright line is the integer: >= 12 fires is the not-a-flat-ceiling signal). **Confirm null:** <= 11 fire. **Refute:** >= 12 fire. Reference: iris 0/49; full closure-signal ~30 (all closed-frame shallow misses). This span-form includes the 19 shallow misses with no annotated closed frame; a fire count near Prediction 4's recovery count means fires land on real closures, while fires far above it concentrated on the 19 zero-closed misses flags non-specific coefficient activity for Predictions 8 and 9 to adjudicate.

**Prediction 6 — ABOVE_LINE PURE-FUSION TEST (the crux).** The 34 above_line misses never dipped below the raw line at all (min_ratio closest 1.02, median 1.24, farthest 1.66), so ANY fire here is closure the rim ratio _provably_ discarded — not a re-reading of a near-dip. This is the hardest, purest fusion channel, and it is the test the document turns on. The witness fires on **<= 3 of 34** (the pure-fusion channel is empty). **Confirm null:** <= 3 fire. **Partial:** 4 to 10 fire (the table is the result). **Refute (real headroom past the rim):** >= 11 of 34 fire (>= 32%) — closure the fixed ratio discarded but the wider mesh carries. Sub-test on the A2 well-above band (17 misses, min_ratio >= 1.24, where the vertical lid chord stayed 24-66% above the line and the mesh barely moved): the witness fires on **<= 3 of 17**; **>= 4 breaks the shared-mesh account most sharply**, because the network would have found closure the mesh supposedly did not encode. Grounds: a closure whose vertical chord barely moves may still be a distinct configuration across the wider point cloud; if that headroom exists at all, it shows here first.

**Prediction 7 — DIFFERENTIAL, where headroom would surface first (mechanism check).** The 15 never_armed misses physically got closer to closure (min_ratio 0.91 to 0.996) than the 34 above_line (never below 1.02, median 1.24), so any genuine learned headroom should surface on never_armed before above_line. `recovered_neverarmed` (of its 14 closed-frame misses) does **not exceed** `recovered_aboveline` (of its 16 closed-frame misses) **by more than 3**, and both counts are reported **as rates against their unequal denominators (14 vs 16)** alongside the raw counts, so a real rate gap is not hidden by a small raw difference. **Confirm null:** `recovered_neverarmed - recovered_aboveline <= 3`. **Refute (headroom concentrated exactly where the aperture came nearest):** never_armed exceeds above_line by >= 4. As a demoted descriptive readout only — never a scored verdict, because at expected counts near 0-3 a rate ratio is a single-blink artefact — the tool also prints the firing rate ordered by band (never_armed >= A1 near >= A2 well-above) so a reader can see whether recovery, if any, falls monotonically with distance from the line. This whole prediction is a conditional refinement: under the predicted null both counts are ~0 and it confirms near-certainly, so it only discriminates _where_ recovery concentrates and is only informative in the refute-Prediction-4 world.

**Prediction 8 — NEGATIVE CONTROL, eyeWide (the anti-closure pole).** Widening is anatomically the opposite of closure, so on a frame a human called shut it should read ~0. (a) Absolute: `peakWide_span >= 0.50` on **<= 2 of the 49** (`eyeWide` = max of indices 21, 22). (b) On the misses where the witness fires, the peak `eyeWide` over the same scored frames is **< 0.50 on >= 90%** of the fired misses; if fewer than 5 misses fire this is reported **N/A**, not confirm. (c) The relative clause `eyeWide_fires < eyeBlink_fires` is required **only when `eyeBlink_fires >= 3`** — specificity is a question only when there is a blink signal that could be spurious, so an all-zero clean null (0 eyeBlink, 0 eyeWide) is not condemned by it. **Confirm (the eyeBlink signal, whatever its size, is closure-specific):** (a) and (b) hold, and (c) where it applies. **Refute / voids interpretability:** eyeWide fires on >= 3 of 49, or eyeWide co-fires at the closure peaks, or (with `eyeBlink_fires >= 3`) `eyeWide_fires >= eyeBlink_fires` — then any Prediction 4/5/6 recovery is non-specific coefficient activity and cannot be read as closure.

**Prediction 9 — SPECIFICITY / SHUFFLE NULL (any recovery must be real, not ambient).** Per miss compute `in_span_peakBlink - open_baseline_peakBlink`, where the open baseline is the peak `eyeBlinkMax` in the matched open window — up to 60 frames before the miss span with `insideSpan = 0`, the same window the iris positive control used (`docs/iris-occlusion.txt` lines 157-169). The elevation statistic is the median of that difference over the 49. Shuffle the {in-span, open-baseline} label **1000 times from one seed fixed here now, seed = 20260902**, recompute the median elevation each time; the observed elevation must exceed the **97.5th percentile** of the shuffled null (one-sided, p < 0.025). One-sided because the direction is fixed in advance: recovery means a _higher_ blink coefficient inside the closure span. **Confirm null:** observed elevation at or below the 97.5th percentile. **Refute:** observed above it (the coefficient rises specifically inside the closure spans). Reference: no effect = elevation ~0, the 50th percentile of the shuffled null. Where the null is run across more than one channel (`eyeBlink`, `eyeSquint`, `eyeWide`), the family is **Holm-corrected** and both raw and corrected p are printed; **all channels are reported, not the best one.**

**Prediction 10 — NO-TRUSTED-FACE NULL (a distinct redirect, not a closure question).** On the **4 no_trusted_face misses** (3 closed-frame), with `result.faceBlendshapes[0]` recorded directly per the extraction contract, the witness fires on **<= 1**. **Confirm null:** <= 1 fire. **Refute:** >= 2 fire — the miss cause for those was the app's face-trust gate rejecting a face whose landmarks and blendshapes were actually usable, which is a gate problem, not a closure-signal problem. Grounds: with no trusted face, FaceMesh delivered no reliable geometry, so the network is fed the same absent input the aperture was; low power (n = 4), but a real test with its own consequence.

## The decision rule, fixed in advance

A closed, jointly-exhaustive set of named categories, evaluated in this order so that the controls gate interpretation before the counts size the decision (this ordering is what resolves the case where a recovery count is high while a control fails):

1. **INCONCLUSIVE** — if Prediction 1 (neutrality) fails, OR Prediction 2 < 90%, OR Prediction 3 fails. Nothing about recovery is interpretable; T or the harness is fixed and the run repeated. No fusion decision.
2. **SUGGESTIVE AND UNCONFIRMED** (in those words) — if the controls in (1) pass but a non-zero recovery fails Prediction 9's shuffle null, or fails Prediction 8, or Prediction 4 lands in [8, 14] / Prediction 6 in [4, 10]. The per-miss table is the result; no full fusion row; question deferred to its own predict-then-verify.
3. **CEILING CONFIRMED (landmark-bounded)** — controls pass, Prediction 4 <= 7 AND Prediction 6 <= 3, with 8/9 clean. No fusion row; the 49 is recorded as a recall ceiling; 11.3 proceeds unblocked. A null here is informative: two independent landmark-fed closure witnesses now agree the closure is invisible to this mesh.
4. **SCOPED HEADROOM** — controls pass, 8 holds, 9 clears, and recovery is concentrated on the never_armed / near-line band (Prediction 7 gap >= 4) with above_line/A2 ~0. A narrowly-scoped fusion row opens before 11.3, gated on its own predict-then-verify.
5. **HEADROOM (full fusion signal)** — controls pass, 8 holds, 9 clears, and Prediction 4 >= 15 or Prediction 6 >= 11. A full fusion row opens before 11.3, gated on its own predict-then-verify; the recovered misses are its regression target.

A null (category 3, and the null side of 2) is **published exactly as readily as a positive one would have been.** A null here settles a real, twice-asked question rather than leaving it open.

## The negative control and chance-rate discipline, fixed in advance

All pinned before the data: (1) the paired permutation null of Prediction 9 — 1000 shuffles from the single fixed seed 20260902, the observed median elevation against the 97.5th percentile, one-sided because the recovery direction is fixed in advance; (2) Holm correction across the `eyeBlink`/`eyeSquint`/`eyeWide` channels with both raw and corrected p printed and all channels reported, not the best; (3) the eyeWide negative control of Prediction 8, gated so a clean all-zero null is not condemned; (4) the two positive controls of Predictions 2 and 3 — the "does it fall on anything?" companions to the "does it fall on the misses?" question, run up front here rather than flagged as a later check, because a null is only meaningful once the instrument is shown to have range; (5) the neutrality control of Prediction 1, which must hold byte-for-byte before any row is scored. The chance-rate reference is stated so falsifiability is visible: no effect = a recovery count at the shared-bottleneck ~0 and an elevation at the 50th percentile of the shuffled null.

## What this cannot answer

- **One vendored model, one corpus.** This tests what _this_ MediaPipe blendshape head extracts from _these_ 8 clips' landmarks, not what any face model or any corpus could.
- **Landmark-bounded by construction.** The head takes zero pixels; a null shows only that a learned read of the same 146 mesh points recovers nothing, never that the closures are unrecoverable by an appearance model.
- **Relative, not absolute.** T = 0.50 asks whether the coefficient crosses a midpoint on these frames, not whether its value is a calibrated closure fraction.
- **Small deep and trust groups.** The `armed_then_dropped` (5) and no_trusted_face (4) groups are low-powered, and the long crossed_line depth is inferred from fully-closed-frame counts, not a recorded min_ratio.
- **Correlation with the annotation, not cause.** A recovered miss means the coefficient fired where a human marked closure; it does not establish why the aperture did not.

## What would count as this being wrong

Binding in advance: if a later run — a cleaner witness, a corrected extraction, a fused detector on fresh footage — reverses any conclusion drawn here, that reversal belongs on the result page in writing, the way the crossed_line and above_line miss-mechanism predictions were refuted in writing on `docs/miss-character.txt` and the UTA-RLDD reversal was recorded on its own result page. A recovery later traced to an artefact — the landmark numbers having shifted under the flag despite Prediction 1, a mis-scored span, a control that should have voided the run — is retracted here, not quietly dropped.

## The per-miss verdict CSV, and what it must contain

The scoring rests on one committed per-miss verdict file with **exactly 67 data rows + 1 header**, one row per miss, joinable 1:1 by `(clip, blink_id)` to the 67-row autopsy and the rearm miss tables — so any row appearing, disappearing, or reordering is itself a neutrality violation and is visible. Produced by `analysis/tools/blendshape_witness.py`; raw per-frame traces stay uncommitted, only this per-blink table lands under `docs/evidence/<date>-blendshape-witness/eyeblink8_blendshape_witness.csv`. Required columns:

- **Join and membership (ride along from the committed autopsy, not re-derived):** `clip`, `blink_id`; `mechanism` (no_trusted_face | crossed_line | above_line); `witness_band` (above_near | above_well | never_armed | armed_dropped | crossed_long | no_trusted_face) — the one derived column that makes Predictions 4-7 and 10 a groupby, above_line split at the median min_ratio 1.24; `min_ratio` (copied through; blank for the long crossed_line and no_trusted_face rows where it is genuinely unrecorded); `measured_frames` (this is 0 on the 4 no_trusted_face rows — the file must not assert "every miss has measured frames," which is false for that group).
- **Span and ground-truth closure:** `startFrame`, `endFrame`, `frameLength`; `fully_closed_frames`; `closed_frame` (bool, reproduces the 30-of-49 and 47-of-67 splits); `scored_on` (`closed_frames` | `full_span`).
- **eyeBlink witness (scored):** `peakBlinkLeft_span`, `peakBlinkRight_span`; `peakBlink_span` (= max over span of `eyeBlinkMax`, the scored quantity); `peakBlink_closed` (max over the fully-closed frames; blank when fully_closed_frames = 0); `peak_frame` (audit; verify it lands on a fully-closed frame when `scored_on = closed_frames`); `peakBlink_span_meanrule`, `peakBlink_span_minrule` (the combining-rule robustness band; peak-of-mean stored explicitly because it is not derivable from per-eye peaks); `T_used` (0.50); `witness_fires`, `witness_recovers` (bools at T = 0.50); `fires_T03`, `fires_T07` (threshold sweep).
- **Negative control (Prediction 8):** `peakWide_span`, `peakWide_at_peak` (`eyeWide` at `peak_frame`); `wide_fires`.
- **Partial-closure cross-check (ride along, NOT scored):** `peakSquint_span`.
- **Specificity (Prediction 9):** `open_baseline_peakBlink` (matched open window); `in_span_minus_baseline_blink`.
- **Neutrality guard (per row):** `still_missed_flag_on` (bool) — must be TRUE on every scored row, or that row is disqualified.

**Column-level rule, stated in advance:** `witness_recovers`, `witness_fires`, and `wide_fires` are the only columns the verdict reads for the pass/fail decision; `peakSquint_span`, `min_ratio`, and `measured_frames` ride along and are not scored.

Two committed companions: `eyeblink8_blendshape_detected_control.csv` (one row per detector-hit closed-frame blink, with the same `peakBlink_closed` and `fires` columns, scoring Prediction 2), and a shuffle-null summary (`blendshape_shuffle_null.txt`: seed 20260902, shuffle count 1000, observed median elevation, and the null's 50th / 95th / 97.5th percentiles with raw and Holm-corrected p per channel, scoring Prediction 9). A provenance sidecar records the flag `outputFaceBlendshapes = true`, model sha256 `64184e22...`, `@mediapipe/tasks-vision` 1.0.1, and the assertion that the 67-row miss set equals the committed rearm anchor. Predictions 3(a), 3(b), 6's A2 sub-test, and 10 are scored from `witness_band` groups in the main table.

This prediction is not edited after the blendshape trace is read; the result arrives in a later commit in `docs/blendshape-witness-result.txt` and can be checked against what is written here.
